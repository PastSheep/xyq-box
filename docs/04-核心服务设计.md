# 04 · 核心服务设计

> 核心服务 = 应用的基础设施，**全部由插件提供**（纪律二）。下表为第一版服务清单与接口草案；
> 每个服务都标注**默认实现插件**——去掉它，服务就消失，依赖它的插件进入 PENDING，应用不会崩。

## 1. 服务总览

| 服务名 | 职责 | 默认实现插件 | 可替换 |
| --- | --- | --- | --- |
| `config` | 按插件分片的配置读写与订阅 | `@xyq-box/plugin-config` | ✅ |
| `logger` | 结构化日志 | `@xyq-box/plugin-logger` | ✅ |
| `storage` | 键值/文档持久化抽象 | `@xyq-box/plugin-storage` | ✅ |
| `views` | UI 扩展点注册与聚合 | `@xyq-box/plugin-views` | ✅ |
| `commands` | 命令面板与快捷键 | `@xyq-box/plugin-commands` | ✅ |
| `permissions` | 权限校验与策略 | `@xyq-box/plugin-permissions` | ✅ |
| `connection` | Node/Web 双端 RPC 桥 | 内核内置（无它则无 UI 通信） | ❌（内核约定） |
| `events` / `logger` 基座 | 事件总线 / 日志基座 | Cordis 内置 | —（框架层） |

`connection` 由内核提供而非插件，是唯一例外——它是「内核-壳」契约的一部分，不参与替换（理由见 §8）。

## 2. config

```ts
interface ConfigService {
  /** 读取某插件的配置（合并默认值 + 用户配置 + intercept） */
  get(pluginId: string): Readonly<unknown>
  /** 读取某插件的配置并校验返回类型 */
  get<T>(pluginId: string): Readonly<T>
  /** 局部更新（按插件名分片写入） */
  set(pluginId: string, patch: unknown): Promise<void>
  /** 订阅某插件配置变更（effect 语义，随插件卸载自动退订） */
  onChange(pluginId: string, listener: (value: unknown) => void): () => void
  /** 全部插件配置的快照（供设置 UI / 导出） */
  snapshot(): Record<string, unknown>
}
```

要点：

- 分片键 = 插件 id；互不干扰；
- 变更 → 内核触发对应插件热重载（HMR 语义）；
- 持久化委托 `storage`；
- 设置 UI 本身是插件（settings 插件消费 `config` + `views` 渲染表单，schema 驱动）。

## 3. logger

```ts
interface LoggerService {
  (scope: string): Logger
  /** 全局级别过滤（可由设置 UI 调节） */
  setLevel(level: 'debug' | 'info' | 'warn' | 'error'): void
  /** 追加输出端（如控制台/文件/UI 面板），插件可注册 */
  addSink(sink: LogSink): () => void
}

interface Logger {
  debug(msg: string, fields?: object): void
  info(msg: string, fields?: object): void
  warn(msg: string, fields?: object): void
  error(msg: string, fields?: object): void
}

interface LogSink {
  write(entry: LogEntry): void   // LogEntry = { time, level, scope, msg, fields }
}
```

要点：

- 默认 sink：Web 端 console + 内存环形缓冲（供诊断面板读取）；桌面端追加文件 sink（可裁剪）；
- 日志面板 = 一个消费 `logger` sink 的 UI 插件，仅当存在时才显示日志；
- **删掉 logger 插件 = 没有任何输出**——发行版包含它，但可裁剪性是可验证的。

## 4. storage

```ts
interface StorageService {
  /** 键值（小型状态） */
  get(key: string): Promise<unknown | undefined>
  set(key: string, value: unknown): Promise<void>
  /** 文档集合（中型数据） */
  collection<T>(name: string): Collection<T>   // { find, insert, update, remove }
  /** 文件（大对象/二进制，仅桌面端有意义） */
  readFile(path: string): Promise<Uint8Array>
  writeFile(path: string, data: Uint8Array): Promise<void>
}
```

要点：

- Web 默认实现：IndexedDB（键值 + 文档）+ 虚拟文件系统（blob）；
- 桌面默认实现：用户数据目录 JSON 文件 + 真实文件系统；
- 存储键建议 `插件id:key` 前缀，避免碰撞；
- 实现可替换：换加密存储、云同步只是「换一个 storage provider 插件」。

## 5. views（UI 扩展点）

```ts
type SlotName = 'root' | 'sidebar' | 'panel' | 'toolbar' | 'statusbar' | 'context-menu' | 'theme' | 'command'

interface ViewDescriptor {
  id: string                    // 全局唯一
  slot: SlotName | string
  title?: string
  icon?: string
  component?: unknown           // 框架组件（SDK 层收敛类型）
  render?: (ctx: ViewContext) => unknown   // 无框架渲染器（替代 component）
  order?: number                // 排序权重
  visible?: () => boolean
  setup?: (ctx: ViewContext) => void | Promise<void>   // 挂载钩子（可做 RPC 预取）
}

interface ViewsService {
  register(descriptor: ViewDescriptor): () => void      // effect：返回退订
  list(slot: SlotName): ViewDescriptor[]
  onChange(listener: () => void): () => void
}

interface ViewContext {
  connection: ConnectionService   // 供 UI 插件调用 Node half
  logger: Logger
  config: ConfigService
  commands: CommandsService
}
```

要点：

- 壳只订阅 `views.onChange` 并渲染 `list(slot)` 结果；新增视图无需改壳；
- 面板系统（拖拽停靠、折叠、布局持久化）本身也是一个布局插件（`@xyq-box/plugin-layout`），占据 `root` slot 并管理 `panel` 子 slot 的布局；
- 描述符同时支持「组件」与「无框架渲染器」两条路，保证框架可换。

## 6. commands

```ts
interface Command {
  id: string
  title: string
  shortcut?: string[]            // 如 ['Ctrl+K', 'Ctrl+P']
  icon?: string
  run(ctx: CommandContext): void | Promise<void>
  when?: () => boolean           // 可用性条件
}

interface CommandsService {
  register(command: Command): () => void
  list(): Command[]
  run(id: string): Promise<void>
  /** 命令面板 UI（插件实现，消费本服务渲染） */
}
```

要点：

- 命令面板 = `@xyq-box/plugin-command-palette` 插件（消费 `commands` + `views`），按下快捷键弹出；
- 快捷键冲突：后注册者生效 + 警告日志（冲突可诊断）。

## 7. permissions

```ts
interface PermissionCheck {
  pluginId: string
  permission: string             // 如 'fs.write:/data/**'
}

interface PermissionsService {
  /** 校验：不通过则抛可读错误；通过返回释放句柄（用于一次性授权） */
  check(req: PermissionCheck): Promise<() => void>
  /** 声明当前插件的权限（从 manifest 读取，安装时登记） */
  declare(pluginId: string, permissions: string[]): void
  /** 用户/策略覆盖（如拒绝某插件某权限） */
  override(pluginId: string, permission: string, allow: boolean): void
}
```

要点：

- 内置插件信任级别 trusted，默认放行；第三方 installed 级别按声明校验；
- 首次触发敏感权限：弹出确认（UI 由 permissions 配套插件渲染），用户选择后记住；
- 沙箱执行列为远期（不改本接口，加执行层）。

## 8. connection（内核内置，双端 RPC 桥）

```ts
interface ConnectionService {
  rpc: {
    /** Node half：注册端点 */
    handle(channel: string, handler: (endpoint: string, payload: unknown) => Promise<{ ok: true; value: unknown } | { ok: false; error: string }>, opts?: { authority?: 'loopback' | 'any' }): () => void
    /** Web half：调用端点 */
    call(channel: string, endpoint: string, payload: unknown): Promise<{ ok: true; value: unknown } | { ok: false; error: string }>
  }
  /** 双端事件推送（Node → Web 单向通知） */
  push(channel: string, event: string, payload?: unknown): void
  onPush(channel: string, handler: (event: string, payload: unknown) => void): () => void
}
```

约定（沿自 DSH 生态实测）：

- payload 必须可 JSON 序列化；**无参数传 `null`，绝不传 `undefined`**；
- 调用方对 `{ ok: false }` 必须打日志，不静默吞掉；
- 端点注册是 effect，插件卸载自动撤销；
- **传输实现可换**：Web 部署用进程内直通，桌面部署（Electron）用 IPC 传输实现，接口不变，插件代码无需感知差异；
- Web-only 部署（无 Node half）时，`connection` 提供进程内直通实现。

## 9. 可选服务（插件生态自行提供）

| 服务 | 说明 |
| --- | --- |
| `http` | 出站网络请求（带 permissions 校验），第三方插件常用 |
| `shell` | 外部进程执行（高危，默认仅内置） |
| `updater` | 插件与发行版更新检查 |
| `i18n` | 国际化：消息目录 + 语言切换 |
| `theme` | 主题管理（CSS 变量集合的切换） |
| `telemetry`（默认关闭） | 匿名统计，opt-in |

## 10. 服务设计评审要点

- [ ] 服务接口最小够用（YAGNI），扩展走插件而非加参数；
- [ ] 服务名与文档一致；TypeScript 有 `declare module` 类型合并；
- [ ] 每个服务都有可替换实现路径（至少文档中写清「如何换」）；
- [ ] 每个服务都有配套的默认实现插件，且可被裁剪验证；
- [ ] 敏感能力（fs/network/shell）必须过 permissions。
