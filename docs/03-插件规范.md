# 03 · 插件规范

> 插件是 xyq-box 的一等公民。本规范定义插件的**包结构、清单、入口、服务契约、配置、权限与分发**。
> 内置插件与第三方插件**遵守同一条规范**，没有特权接口。

## 1. 插件包结构

```
my-plugin/
├── package.json          # 包元数据 + xyq-box manifest（见 §2）
├── lib/
│   ├── index.ts          # Node half 入口（逻辑/服务），可缺省（纯 UI 插件）
│   └── client.ts         # Web half 入口（视图组件），可缺省（纯逻辑插件）
├── src/                  # 源码（构建到 lib/，或直接以 ts 分发见 §7）
├── README.md
└── LICENSE
```

包名约定：

- 内置插件：`@xyq-box/plugin-<name>`；
- 第三方插件：任意合法 npm scope/裸名，建议 `@<作者>/xyq-<name>` 或 `xyq-plugin-<name>`；
- 每个插件**一个包**，每个包**一个插件**（不强求，但推荐；拆分利于独立装卸）。

## 2. Manifest（package.json#xyqBox）

```jsonc
{
  "name": "@xyq-box/plugin-file-browser",
  "version": "0.1.0",
  "main": "lib/index.js",
  "exports": { ".": "./lib/index.js", "./client": "./lib/client.js" },
  "xyqBox": {
    "id": "@xyq-box/plugin-file-browser",          // 全局唯一 ID，= 包名（推荐）
    "title": "文件浏览器",
    "description": "侧边栏文件树与常用文件操作",
    "author": "xyq-box team",
    "license": "MIT",
    "engine": { "xyqBox": "^0.1.0", "cordis": "^4.0.0" },   // 内核兼容声明
    "permissions": ["fs.read", "fs.write"],                  // 权限声明（见 §6）
    "entry": { "node": "lib/index.js", "client": "lib/client.js" },
    "provides": ["fileBrowser"],              // 冗余声明能力（与代码 provide 对应）
    "requires": ["views", "storage", "config"] // 冗余声明依赖（与代码 inject 对应）
    "homepage": "...",
    "keywords": ["xyq-box", "plugin"]
  }
}
```

> `provides` / `requires` 与代码里的 `provide` / `inject` 互为镜像：代码字段决定运行时行为，manifest 字段用于**静态分析、市场展示与冲突检测**。

## 3. 入口约定

### 3.1 Node half：`lib/index.ts`

```ts
import { Context, Service } from 'cordis'

export const name = 'my-plugin'
export const inject = ['logger']          // 可选：硬依赖
export const provide = ['myService']      // 可选：提供的能力
export const Config = Schema.object({     // 可选：配置 schema（schemastery DSL）
  enabled: Schema.boolean().default(true).description('是否启用'),
})

export function apply(ctx: Context) {
  ctx.logger('my-plugin').info('loaded')
  // 注册服务 / 事件 / RPC 端点……全部走 effect API，卸载自动清理
}
```

插件三种形态任选其一：函数（如上）、类（`new (ctx, config)`）、对象（`{ apply(ctx, config) }`）。

### 3.2 Web half：`lib/client.ts`

Web half 面向浏览器环境（UI 组件、主题、前端逻辑），以「视图描述符」形式注册到 views 服务：

```ts
import { defineView } from '@xyq-box/sdk'

export default defineView({
  slots: ['sidebar'],             // 挂到哪些扩展点
  title: '文件浏览器',
  icon: 'folder',
  component: MyFileTree,          // 组件（框架相关，见 §8）
  // 与 Node half 通信：
  setup(ctx) {
    const res = await ctx.connection.rpc.call('/file-browser', 'list', { path: '/' })
    if (!res.ok) ctx.logger.warn('list failed: ' + res.error)
  },
})
```

**双端生命周期一致**：插件卸载时，其注册的视图与 RPC 消费一并撤销。

## 4. 服务契约（provide / inject）

- **命名空间**：服务名处于每个应用一个的扁平命名空间。`@xyq-box/plugin-*` 内置服务占短名（`config`、`logger`、`storage`、`views`、`commands`、`permissions`、`connection`）；第三方插件服务建议 `前缀.名字`（如 `fileBrowser`、`git.status`），避免冲突；
- **提供服务**：继承 `Service` 基类，`super(ctx, '服务名')`；TypeScript 侧用 `declare module 'cordis'` 合并 `Context` 接口以获类型提示；
- **消费服务**：`export const inject = ['服务名']` 硬依赖（缺失则 PENDING）；可选能力用 `ctx.get('服务名')` 探测；
- **替换实现**：任何服务都可被替换——新插件注册同名服务，旧 provider 卸载后消费者自动重连（架构见 02-§2.3）。

## 5. 配置

- 每个插件通过 `Config` 字段声明 schema（schemastery DSL，兼容 Standard Schema）；
- 装载时校验：非法配置 → fiber FAILED，错误信息包含字段路径；
- 用户配置经 `ctx.config` 服务按插件名分片读写与订阅；
- 变更即热重载：配置变化 → 内核重载该插件（无需重启应用）。

## 6. 权限

```jsonc
// manifest 权限声明示例
permissions: [
  "fs.read",           // 任意路径读取
  "fs.write:/data/**", // 限定路径的写权限（支持 glob）
  "network:fetch",     // 出站 HTTP
  "shell:run"          // 执行外部进程（高危）
]
```

- 权限名采用 `域:动作[:路径/限定]` 格式；
- 内置插件（trusted）默认全权；第三方插件权限经 `ctx.permissions` 校验，首次使用可弹确认；
- 声明了但未使用的权限无害；**未声明即使用 → 拒绝**（最小权限原则）；
- 权限策略本身可由插件扩展（如企业策略插件）。

## 7. 分发形态

| 形态 | 方式 | 场景 |
| --- | --- | --- |
| 内置 | monorepo 内 `@xyq-box/plugin-*`，随发行版打包 | 默认基础设施与旗舰功能 |
| 本地 | `plugins/` 目录或绝对路径（如 `./local-plugins/my-thing`） | 开发调试、私有插件 |
| 远程 | npm 包 或 GitHub 仓库（`github:owner/repo#tag`） | 第三方分发（M3 落地） |

安装动作 = 下载 + 校验（engine/依赖/权限声明）+ 写入插件清单 + 热装载。

## 8. UI 框架无关性（待定，见 ADR）

- views 服务只认**视图描述符**（slot、title、icon、组件引用、setup 钩子），不绑定具体组件框架；
- 第一版建议 React（生态与 DSH 经验一致），但协议保持框架无关：若换 Vue/Solid，只换「UI 聚合插件」与 SDK 的 `defineView` 适配层；
- 主题贡献走 CSS 变量协议，与框架无关。

## 9. 版本与兼容

- 插件遵循 semver；
- `engine.xyqBox` 声明兼容的内核版本（`^0.1.0`），安装时校验；
- **服务契约版本化**：提供服务在 manifest 的 `provides` 中可标注契约版本（如 `fileBrowser@1`）；消费者 `requires` 声明所需契约版本，冲突或缺失时给出可读诊断；
- 破坏性变更：主版本号提升 + 变更日志；内核在 M0 起就固化「契约演进」规则（additive-only 于次版本内）。

## 10. 开发体验

- 本地开发：`xyq dev` 启动 Web 壳 + HMR，插件改代码即热重载（沿用 Cordis HMR 语义）；
- 脚手架：`xyq create <name>` 生成满足本规范的包骨架（M0 交付）；
- 校验：`xyq verify <dir>` 静态检查 manifest / engine / 权限声明 / 入口存在（对应 DSH 生态的 verify-pack 经验）；
- 诊断：内核暴露插件清单实时状态（fiber 状态、依赖图、错误），UI 由内置 diagnostics 插件渲染。

## 11. 规范自查清单（插件作者）

- [ ] `xyqBox` manifest 字段齐全（id 唯一、engine 声明、permissions 声明）；
- [ ] 入口文件存在且可被 `@xyq-box/sdk` 类型检查通过；
- [ ] 服务名不与内置短名冲突（第三方用 `前缀.名字`）；
- [ ] 配置有 schema，缺省值友好；
- [ ] 所有注册均为 effect 语义，卸载干净；
- [ ] RPC payload 可 JSON 序列化，无参数传 `null`；
- [ ] 未声明权限绝不使用。
