# 05 · 技术选型与仓库结构

## 1. 核心依赖

| 依赖 | 用途 | 版本策略 |
| --- | --- | --- |
| `cordis` | 插件运行时内核 | v4（见 ADR：上游 `4.0.0-rc.8` vs `@deepseek-ai/cordis` 4.0.1 fork，M0 前定案并锁版） |
| `schemastery` | 配置 schema DSL（实现 Standard Schema，`Config` 字段直接兼容） | 最新稳定 |

| TypeScript | 全仓类型 | `strict` 开启 |
| pnpm | 包管理 / workspace | ≥ 9 |
| React（待 ADR 定案） | UI 框架（第一版建议） | 18/19 |
| Vitest | 单测 | 最新 |
| ESLint + Prettier | 静态检查与格式化 | 标准配置 |
| Changesets | 版本管理与 changelog | 标准 |

> cordis 生态的 `cosmokit`（工具库）按需引入，不整包依赖。

## 2. Monorepo 布局（pnpm workspaces）

```
xyq-box/
├── docs/                       # 设计文档（本目录）
├── packages/
│   ├── core/                   # @xyq-box/core —— 内核
│   │   ├── src/                #   引导、插件管理器、清单加载器、配置仓库
│   │   └── tests/
│   ├── sdk/                    # @xyq-box/sdk —— 插件 SDK
│   │   └── src/                #   defineView / definePlugin / 类型合并助手
│   ├── host-web/               # @xyq-box/host-web —— 浏览器壳
│   │   └── src/                #   启动内核 + 默认清单 + UI 根渲染
│   ├── host-desktop/           # @xyq-box/host-desktop —— 桌面壳（M2）
│   └── plugins/                # 内置插件（每个子目录一个包）
│       ├── config/             #   @xyq-box/plugin-config
│       ├── logger/             #   @xyq-box/plugin-logger
│       ├── storage/            #   @xyq-box/plugin-storage
│       ├── views/              #   @xyq-box/plugin-views
│       ├── commands/           #   @xyq-box/plugin-commands
│       ├── command-palette/    #   @xyq-box/plugin-command-palette
│       ├── permissions/        #   @xyq-box/plugin-permissions
│       ├── layout/             #   @xyq-box/plugin-layout（面板系统）
│       ├── settings/           #   @xyq-box/plugin-settings（设置 UI）
│       ├── diagnostics/        #   @xyq-box/plugin-diagnostics（插件状态面板）
│       └── hello/              #   @xyq-box/plugin-hello（示例/样板插件）
├── apps/                       # 可执行入口（薄）
│   └── xyq/                    #   命令行：xyq dev / build / create / verify
├── package.json
├── pnpm-workspace.yaml
├── tsconfig.base.json
├── .npmrc                      # shamefully-hoist=false 等 pnpm 约定
└── README.md
```

原则：

- **core 零业务**；sdk 零运行时依赖（纯类型 + 小工具）；host 只是装配；
- 插件间依赖仅通过服务（`ctx`），**不允许**插件 A import 插件 B 的包；
- 内置插件用 workspace 协议（`workspace:*`）互不引用，只依赖 `@xyq-box/core` / `@xyq-box/sdk` 与 cordis；
- 所有包 `strict` 类型检查 + 单测作为发布门槛。

## 3. 构建与运行

| 命令 | 作用 |
| --- | --- |
| `pnpm -r build` | 全仓构建（tsc/esbuild） |
| `pnpm dev` | 起 Web 壳（Vite）+ 内核 HMR |
| `pnpm test` | Vitest 全仓单测 |
| `pnpm lint` / `pnpm typecheck` | 静态检查 |
| `pnpm changeset` | 版本管理 |
| `pnpm xyq create <name>` | 生成插件骨架 |

## 4. CI（M0 起）

- GitHub Actions：`typecheck → lint → test → build` 四段；
- 插件规范校验（`xyq verify`）纳入 CI 对 `packages/plugins/*` 的检查；
- 变更集驱动版本与 changelog。

## 5. 依赖纪律（沿自 DSH 生态血的教训）

- **宿主/框架包只进 `peerDependencies`**：任何直接依赖 cordis 副本的包（尤其跨进程/跨 realm 场景）会造成 Symbol 分裂、运行时身份不一致——插件包一律把 `cordis` 声明为 peerDependencies，由内核提供单例；
- 同理，若选 React：插件把 `react`/`react-dom` 放 peerDependencies；
- 锁定 pnpm `autoInstallPeers=false`，防止 peer 被自动安装出副本；
- 包内不打包框架代码，只发布产物与声明。
