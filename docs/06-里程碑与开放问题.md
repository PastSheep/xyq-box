# 06 · 里程碑与开放问题（ADR）

## 1. 里程碑路线图

### M0 —— 内核骨架（评审通过后即启动）

交付物：

- [ ] 仓库脚手架：pnpm workspace、tsconfig、ESLint、Vitest、Changesets、CI（typecheck/lint/test/build）；
- [ ] `@xyq-box/core`：Cordis 引导 + 插件管理器（清单加载、装载/卸载/热重载、fiber 状态诊断）；
- [ ] `@xyq-box/sdk`：`defineView` / `definePlugin` / 类型合并助手 / `xyq verify` 校验器；
- [ ] `@xyq-box/plugin-hello` 示例插件 + 单测（装载→卸载→重载）；
- [ ] `apps/xyq`：`dev` / `create` / `verify` 命令；
- [ ] 验收标准：删掉 logger 插件 → 无日志输出且应用不崩；装载未知服务依赖 → 插件 PENDING 且有诊断。

### M1 —— Web 壳与 UI 扩展点

- [ ] `@xyq-box/host-web`：Vite 壳，启动内核 + 默认清单 + UI 根；
- [ ] `plugin-views` + `plugin-layout`：面板系统（拖拽停靠、折叠、布局持久化）；
- [ ] `plugin-commands` + `plugin-command-palette`：命令面板与快捷键；
- [ ] `plugin-config` + `plugin-settings`：schema 驱动的设置 UI；
- [ ] `plugin-diagnostics`：插件实时状态面板（fiber 状态、依赖图、日志）；
- [ ] 验收：一个第三方风格插件（带权限声明）可经本地目录安装、热重载、卸载，全程不动壳代码。

### M2 —— 桌面壳

- [ ] `@xyq-box/host-desktop`（Electron 或 Tauri，见 ADR-D2）；
- [ ] `storage` 桌面实现（用户数据目录 + 真实 fs）；`logger` 文件 sink；
- [ ] 托盘、窗口状态、自动更新（如选 Electron：electron-updater；Tauri：内置 updater）；
- [ ] 分发：安装包（nsis/dmg/AppImage）与签名。

### M3 —— 插件生态

- [ ] 远程插件源：npm / GitHub 安装、engine 与依赖校验、权限声明检查；
- [ ] 插件市场 UI（浏览、安装、更新、卸载）；
- [ ] 沙箱执行评估（vm / worker 隔离，若可行则落地）。

### M4 —— 打磨与发布

- [ ] i18n、主题生态、遥测（opt-in）；
- [ ] 完整文档站、示例插件集、社区指南；
- [ ] 1.0 发布与契约冻结。

## 2. 开放决策清单（ADR）

> 每项决策记录：背景、选项、倾向、影响。M0 开工前需要定案的用 ⛔ 标记。

### D1 ⛔ Cordis 来源：上游 vs DSH fork

- 背景：cordis v4 上游 npm 最新为 `4.0.0-rc.8`（v4 尚未正式发布）；DeepSeek Harness 使用 `@deepseek-ai/cordis` 4.0.1（v4 线 fork，含少量 DSH 侧改动，如 `Context.is()` 跨 realm 判定等）；
- 选项：
  - A. 上游 `cordis`（社区标准，未来 4.0 正式版同源）；
  - B. `@deepseek-ai/cordis` fork（与 DSH 生态互通，本机已有真实运行经验与文档）；
- 倾向：**A（上游）**，若 v4 正式版发布周期过长则临时锁 `4.0.0-rc.x` 固定版本；fork 的增量特性（跨 realm）属于 M3 沙箱话题，届时可再评估；
- 影响：peerDependencies 声明、类型合并的模块名（`declare module 'cordis'` vs `'@deepseek-ai/cordis'`）——**M0 一旦写死，全仓统一，不可混用**（Symbol 分裂风险）。

### D2 桌面壳：Electron vs Tauri

- 背景：桌面壳在 M2；Web 壳先行不阻塞；
- 选项：
  - A. Electron：生态成熟、Node 能力直通、DSH 同技术栈（经验可复用）、体积大；
  - B. Tauri 2：体积小、内存低、Rust 侧系统能力、需维护 Rust 端、RPC 桥多一层；
- 倾向：**先 Web 壳（M1）验证协议，D2 推迟到 M2 开工前决策**；届时若团队无 Rust 投入意愿则选 Electron；
- 影响：storage/logger 桌面实现、自动更新链路、打包工具链。

### D3 UI 框架：React vs Vue vs Solid

- 背景：views 协议框架无关（03-§8），但第一版需要定一个；
- 选项：React（生态最大、DSH 经验）、Vue（上手快）、Solid（细粒度响应式、体积小）；
- 倾向：**React**（组件生态与 DSH 侧经验一致，面试/招聘友好）；
- 影响：SDK `defineView` 的组件类型、布局插件实现、样式方案（CSS 变量 + CSS Modules 或 Tailwind）。

### D4 配置格式与存放

- 倾向：**JSON 文件起步**（`plugins.json` 清单 + `config/` 分片），YAML 可选；Web 端经 IndexedDB 持久化同一结构；
- 影响：config 服务实现、迁移工具。

### D5 插件加载器：自研 vs 复用 cordis-loader

- 倾向：**复用 cordis 生态的 loader 模式**（DSH 的 `@deepseek-ai/cordis-plugin-loader` 是现成参考），自研只做「清单解析 + 安装产物路径解析」薄层；
- 影响：HMR 实现成本、组合语法（类 cordis.yml）。

### D6 构建产物：tsc vs esbuild

- 倾向：库用 `tsc`（d.ts 齐全），壳用 `Vite/esbuild`（快）；发布用 `pnpm pack` 前校验（对应 DSH 的 verify-pack 经验）；
- 影响：SDK 类型可达性、插件 TS 分发（直接发布 `src/` + ts 运行时加载，M1 再定）。

## 3. 风险登记

| 风险 | 等级 | 缓解 |
| --- | --- | --- |
| cordis v4 未正式发布（rc），API 可能微调 | 中 | 锁版本 + 契约测试（把核心 API 用法固化进单测） |
| 插件热重载的边界（配置变更 vs 代码变更语义） | 中 | M0 就做 HMR 集成测试；沿用 Cordis 官方 HMR 语义 |
| 双端 RPC 的调试复杂度 | 中 | 统一 payload 约定（`null` 而非 `undefined`）+ 调用侧强制打日志；诊断面板可视化 RPC 流量（M1） |
| 服务替换引发插件风暴（连锁重载） | 低 | 依赖图可视化 + 重载风暴节流（同一次变更合并重载） |
| 第三方插件权限滥用 | 中 | 权限声明必填、默认拒绝、首次使用确认；M3 评估沙箱 |
